## 멘토에게
- 미션과 더불어, 코드 전반적인 리팩토링을 진행했습니다.
  - `prismaClient.ts`를 생성하여 Prisma 인스턴스를 공용으로 관리하도록 구성하여, 
DB 커넥션 관리와 테스트 용이성이 향상되었습니다.
  - 기존의 `res.status(...).json({ message })` 패턴을 제거하고 `CustomError` 클래스를 도입하여,
에러를 `throw` → `errorHandler` 미들웨어에서 중앙 처리하는 구조로 변경했습니다.
- 심화 요구사항(Layered Architecture)에 따라, Service ↔ Repository 계층을 분리했습니다.
  - Prisma 호출 로직을 Repository 계층으로 이관하고, Service는 검증/권한 체크 등 비즈니스 로직만 담당하도록 구조화했습니다.
  - Controller는 Service만 바라보도록 설계하여, 계층 간 의존성과 테스트 용이성을 개선했습니다.
- 심화 요구사항에 따라, DTO를 활용하여 타입 체계화를 적용했습니다.
  - 모든 함수에 입출력 타입을 지정하고, 복잡한 객체는 `CreateDto`, `UpdateDto`, `PublicType` 같은 방식으로 구분했습니다.
  - `Omit`, `Pick`, `NonNullable` 등 TS 유틸리티 타입을 적극 활용하여, 중복 타입 정의를 제거했습니다.
- Controller 함수에 JsDoc 주석을 추가하여, 각 API의 역할과 throws 예외 상황을 명시했습니다.
