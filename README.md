## 멘토에게
- 기본적인 미션 요구사항은 전부 구현하였으며, 이외의 임의 구현 내용을 이하 기재합니다.
- 알림 생성 시 멱등성을 보장했습니다.  
  - `dedupKey`를 설계하고, `userId`, `type`, `entityType`, `entityId`, `dedupKey`를 묶은 복합 유니크 제약을 추가했습니다.  
  - Repository 단에서는 `upsert`를 적용하여 동일 이벤트로 인한 중복 알림이 발생하지 않도록 했습니다.  
- 알림 읽음 처리에도 멱등성을 적용했습니다.  
  - `updateMany({ id, userId, isRead: false })`를 사용하여, 중복 호출이나 멀티탭 환경에서도 안정적으로 동작하도록 했습니다.  
- 스키마 최적화를 진행했습니다.  
  - `@@unique([...dedupKey])`로 멱등성을 보장했고, `@@index([userId, isRead])`를 추가하여 미읽음 카운트 조회 성능을 개선했습니다.  
- 라우팅 및 WebSocket 부트스트랩을 정리했습니다.  
  - `initWs(server)` 형태로 attach 대상을 수정하여 HTTP 서버 기준으로 안정화했습니다.  
  - 알림 라우트는 `/notifications/*` 하위로 일원화하여 관리 포인트를 단순화했습니다.  
- 알림 상태 일괄 처리를 위한 API를 추가했습니다.  
  - `PATCH /notifications/read-all?before=ISO8601`로 특정 시점 이전의 알림을 한 번에 읽음 처리할 수 있도록 했습니다.  
- 읽음 동기화 이벤트를 추가했습니다.  
  - `notification:read`, `notification:read-all` 이벤트 상수를 정의하고, 서버 측에서 브로드캐스트할 수 있는 훅을 마련했습니다.  
- WebSocket 방어 로직을 추가했습니다.  
  - 소켓 서버 미초기화나 에러 발생 시 try/catch로 감싸 서버 전체 흐름이 방해받지 않도록 했습니다.
- 실서비스 구현 시에는 아래와 같이 개선하려 합니다.
  - (멀티 인스턴스 사용 시에) Redis Adapter 도입하여 서버 간 Websocket 이벤트 공유.
  - 미읽음 카운트를 Redis 캐시에 유지하여 조회 성능 향상. insert/update 시에는 캐시 갱신하여 최적화.
  - 대량 이벤트 처리 시에 워커 풀 기반 동시성 제한 도입.
